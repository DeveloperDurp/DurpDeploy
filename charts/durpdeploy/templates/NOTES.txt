STEP 1 — Encryption key
================================================================
The Deployment requires Secret {{ include "durpdeploy.secretKeyName" . }}
in namespace {{ .Release.Namespace }} with key `secret-key`.
The durpdeploy binary refuses to start without a valid 32-byte key.

If you brought your own Secret (secretKey.existingSecret), skip this step.

Otherwise, generate one and patch it in:

  KEY=$(openssl rand -base64 32)
  kubectl create secret generic \
    {{ include "durpdeploy.secretKeyName" . }} \
    -n {{ .Release.Namespace }} --from-literal=secret-key="$KEY" \
    --dry-run=client -o yaml | kubectl apply -f -
  unset KEY

After manually updating a Secret, restart the Deployment explicitly:

  kubectl rollout restart deploy/{{ include "durpdeploy.fullname" . }} -n {{ .Release.Namespace }}

The checksum annotation triggers rollout only when Helm renders changed values.
Back up the matching encryption key separately from the database.

================================================================
STEP 2 — Postgres
================================================================
The chart does not install Postgres. Supply a reachable server.
Configure the connection as follows:

{{- if .Values.externalPostgres.dsnSecret.name }}

The Deployment loads its complete DSN from Secret
{{ .Values.externalPostgres.dsnSecret.name }} with key
{{ .Values.externalPostgres.dsnSecret.key }} in namespace {{ .Release.Namespace }}.
This replaces the connection fields and password Secret reference.
{{- else }}

  {{ .Values.externalPostgres.host }}:{{ .Values.externalPostgres.port }}
  database: {{ .Values.externalPostgres.database }}
  user:     {{ .Values.externalPostgres.username }}

{{- if and .Values.postgres.enabled (not .Values.postgres.existingSecret) }}

The chart rendered a Secret named {{ include "durpdeploy.postgresSecretName" . }}
holding the password. Set the same password in your Postgres server, then
restart the Deployment:

  PGPASSWORD=$(kubectl get secret {{ include "durpdeploy.postgresSecretName" . }} \
    -n {{ .Release.Namespace }} -o jsonpath='{.data.password}' | base64 -d)
  # ... configure Postgres with that password
  kubectl rollout restart deploy/{{ include "durpdeploy.fullname" . }} -n {{ .Release.Namespace }}
{{- else if .Values.postgres.existingSecret }}

The chart is using existing Secret {{ .Values.postgres.existingSecret }} for
the Postgres password. Make sure it contains a key named `password`.
{{- else }}

The chart does not create a Postgres password Secret with the default values.
Create the required Secret in this release's namespace and configure Postgres
with the same password:

  PG_PASSWORD=$(openssl rand -hex 32)
  kubectl create secret generic {{ include "durpdeploy.postgresSecretName" . }} \
    -n {{ .Release.Namespace }} --from-literal=password="$PG_PASSWORD"
  # ... configure Postgres with that password, then unset PG_PASSWORD
{{- end }}

The Deployment loads this Secret into PGPASSWORD before its database DSN.
The driver reads the password separately, without URL interpolation.
For additional connection options, use externalPostgres.dsnSecret.
{{- end }}

================================================================
STEP 3 — Create the first admin user
================================================================
Once the pod is Running, exec in and run:

  ADMIN_PASS='<strong-password>'
  kubectl exec deploy/{{ include "durpdeploy.fullname" . }} -n {{ .Release.Namespace }} -- \
    durpdeploy admin create --email admin@example.com --password "$ADMIN_PASS"

(Or use the durable approach: a one-shot Job with the same command — see
the chart README.)

================================================================
STEP 4 — Reach the UI
================================================================
{{- if .Values.ingress.enabled }}

Ingress enabled. Visit:
{{- range .Values.ingress.hosts }}
  https://{{ .host }}
{{- end }}
{{- else }}

Ingress is not enabled. To reach the UI from outside the cluster:

  kubectl port-forward -n {{ .Release.Namespace }} svc/{{ include "durpdeploy.fullname" . }} 8080:{{ .Values.service.port }}
  open http://localhost:8080

For TLS termination and rate limiting, front the Service with an Ingress
or a managed load balancer — the binary speaks plain HTTP on :8080.
